# TradingView alerts for tvbridge

How to make TradingView send alerts that tvbridge accepts. Read the main
[README](../README.md) first. Start in **paper** mode.

## 1. Requirements

- **TradingView Essential plan or higher.** Webhook notifications are a paid-plan feature.
- **Two-factor authentication (2FA) on** in your TradingView account. TradingView does not
  allow webhook alerts without it.
- **Port 443 only.** TradingView only delivers webhooks to the standard ports (80/443) and
  rejects URLs with any other port. The ngrok HTTPS URL uses 443; never add a port number.
- tvbridge installed with the ngrok tunnel running: `tvbridge doctor` is all OK.
- Your secret: the value of `server.secret` in `~/.tvbridge/config.json` (generated by
  `tvbridge init`).

## 2. Webhook URL

```
https://<your-ngrok-domain>/webhook
```

For example `https://calm-fox-123.ngrok-free.app/webhook`. `install.sh` and
`tvbridge ngrok-config` print it. Paste it in the alert dialog under **Notifications ->
Webhook URL**. tvbridge answers within a second; TradingView gives up on slow endpoints
after a few seconds.

## 3. Payload schema

The alert **message** must be one JSON object (max 8 KB). Field names are case-sensitive.

| Field | Aliases | Required | Value | Notes |
|---|---|---|---|---|
| `secret` | `passphrase` | always | string | Must equal `server.secret`. Compared in constant time, never stored or logged. Wrong or missing: HTTP 401. |
| `time` | `timenow`, `fired` | always | `"{{timenow}}"` | ISO-8601 UTC as TradingView sends it (`2026-10-01T09:56:00Z`); epoch seconds or milliseconds also work. Entries are refused if older than 120 s on arrival (`STALE`) or more than 30 s in the future (`FUTURE`). Exits fail open: a future-dated close is accepted, a late one up to 15 minutes if no position on that symbol/side was opened after it fired; any refused exit sends a critical alert. Missing: `NO_TIME`. |
| `symbol` | `ticker` | all but `close_all` | `"{{ticker}}"` | `EURUSD`, `OANDA:EURUSD`, `EUR/USD` or `EURUSD.h` all become `EURUSD`, then MT5 `EURUSD.h`. Must be in `symbols.allowed`/`symbols.specs` (`SYMBOL_NOT_ALLOWED`); a close is also accepted for a symbol with a spec or an open position. Missing: `NO_SYMBOL`. |
| `action` | see table below | yes* | string | Case-insensitive. Unknown: `BAD_ACTION`. *May be omitted when `position`/`market_position` is `flat` (means close). |
| `position` | `market_position` | no | `"{{strategy.market_position}}"` | `flat` with no action means close. `flat` with `buy`/`sell` also means close of the side that order closed (`sell` + `flat` closes longs, `buy` + `flat` closes shorts): that is how a strategy exit looks. `sell` while still `long` (or `buy` while still `short`) is a partial exit and is refused (`BAD_ACTION`, "PARTIAL_EXIT"). |
| `price` | `close` | entries | `{{close}}` (a number, no quotes needed) | Reference price for sizing and SL/TP side checks. Missing: `NO_PRICE`. |
| `sl` | `stop`, `stop_loss` | entries | absolute price | Stop-loss price, sent to MT5 with the order. `0`, `""`, `null` or `NaN` mean "not set", and an entry without it is refused (`SL_MISSING`). |
| `tp` | `take_profit`, `limit` | no | absolute price | Take-profit price. `0`/empty means none. |
| `risk_pct` | `risk` | no | number (percent) | Per-alert risk override, e.g. `0.25`. Always capped by `risk.max_risk_per_trade_pct`. |
| `quote_usd` | | crosses | number | USD value of one unit of the quote currency, e.g. for EURGBP the GBPUSD rate. Not needed for xxxUSD or USDxxx pairs. Pine: `request.currency_rate(syminfo.currency, "USD")`. Missing for a cross: `NO_FX_RATE`. |
| `side` | | close only | `buy`/`sell`/`long`/`short` | Restricts a close to positions on that side. Omitted: both sides (or the side implied by `market_position` `flat`, see above). |
| `id` | | no | string (max 128) | Your idempotency key: it must be **unique per firing**. A TradingView retry (same action + id, same symbol and time) is ignored as a duplicate. The same id from another firing is a collision: an exit is processed under a new id with a warning, an entry on another symbol likewise, an entry on the same symbol is refused (`ID_REUSED`). Never use `{{strategy.order.id}}` or a fixed text. Without it, tvbridge derives an id from action, symbol, side, price, sl, tp, time and strategy. |
| `strategy` | | no | string (max 64) | Label shown in events and notifications. |
| `comment` | | no | string (max 24) | Short label stored with the signal; default `tvb`. |
| `order` | | no | JSON object, or a string containing one | Merged over the outer fields; **its keys win**. This is where `{{strategy.order.alert_message}}` goes. |

Numbers may be JSON numbers or numeric strings (`1.0855` or `"1.0855"`). No thousands
separators. Anything non-numeric gives `BAD_NUMBER`.

### Actions

| You send | Meaning |
|---|---|
| `buy`, `long` | Open a long position (an entry: goes through the risk guard). |
| `sell`, `short` | Open a short position (an entry). |
| `close`, `exit`, `flat`, `close_position` | Close the positions on `symbol` (only those on `side` if given). Always allowed, even when paused or halted. |
| `close_all`, `closeall`, `flatten`, `flatten_all` | Close every position on the account. `symbol` not needed. |
| `sync` | Mirror mode: the alert reports the strategy's resulting position and tvbridge makes MT5 match it. See [section 10](#10-mirror-mode). |

An entry against an open opposite position (a `sell` while long) first closes that position
when `risk.reverse_on_opposite` is true (default) -- even if the entry itself is then refused
(paused, halted, stale, no stop-loss, outside trading hours). Then the entry is checked as
usual. An entry that waited in the queue while a close for that symbol (or a close_all)
arrived is dropped (`SUPERSEDED_BY_CLOSE`).

## 4. Message templates

Replace `PASTE_YOUR_SECRET` with your secret **in the alert dialog only**. Keep the
placeholders exactly as written. `{{close}}`, `{{plot(...)}}` and
`{{strategy.order.alert_message}}` have **no quotes** around them.

### (a) Pine strategy (recommended)

Give every `strategy.entry`, `strategy.exit` and `strategy.close` call an `alert_message`
containing a JSON object. See
[tvbridge_example_strategy.pine](tvbridge_example_strategy.pine): entries send
`{"action":"buy","sl":...,"tp":...,"quote_usd":...}` and exits send `{"action":"close"}`.

Create the alert on the strategy (Condition: your strategy, *Order fills only*) with this
message:

```json
{"secret":"PASTE_YOUR_SECRET","time":"{{timenow}}","symbol":"{{ticker}}","price":{{close}},"order":{{strategy.order.alert_message}}}
```

What tvbridge then receives for an entry:

```json
{"secret":"...","time":"2026-10-01T09:56:00Z","symbol":"EURUSD","price":1.08550,"order":{"action":"buy","sl":1.08250,"tp":1.09150,"quote_usd":1,"strategy":"tvb-example"}}
```

**Every order call in the script must have an `alert_message`.** An order without one
leaves `"order":}` in the message, which is invalid JSON (`BAD_JSON`), and that alert is
lost. For an exit, the position then stays open with only its server-side SL/TP.

### (b) Indicator: `alertcondition()` or `alert()`

With `alertcondition()` the message is fixed text, so put the computed levels in plots and
reference them with `{{plot("title")}}`:

```pine
plot(longSL, "Long SL", display = display.data_window)
plot(longTP, "Long TP", display = display.data_window)
alertcondition(longSignal, "tvbridge long", "edit the message in the alert dialog")
```

Alert dialog message (one alert per direction; the short one uses `"action":"sell"` and
the short plots):

```json
{"secret":"PASTE_YOUR_SECRET","time":"{{timenow}}","symbol":"{{ticker}}","price":{{close}},"action":"buy","sl":{{plot("Long SL")}},"tp":{{plot("Long TP")}},"strategy":"my-indicator"}
```

With `alert()` you build the JSON in code. The alert condition is then *Any alert()
function call* and the dialog's message box is **not used**, so the secret has to live in
the script (e.g. an `input.string`). Never publish or share such a script, and keep it
private.

```pine
secret = input.string("", "tvbridge secret", display = display.none)
if longSignal and barstate.isconfirmed
    alert('{"secret":"' + secret + '","time":"' + str.format_time(timenow, "yyyy-MM-dd'T'HH:mm:ss'Z'", "UTC") + '","symbol":"' + syminfo.ticker + '","price":' + str.tostring(close, format.mintick) + ',"action":"buy","sl":' + str.tostring(longSL, format.mintick) + '}', alert.freq_once_per_bar_close)
```

### (c) Manual close and close_all

Useful as hand-made alerts on a chart (e.g. "close EURUSD if price crosses 1.0700").

Close all positions on the chart's symbol:

```json
{"secret":"PASTE_YOUR_SECRET","time":"{{timenow}}","symbol":"{{ticker}}","action":"close"}
```

Close only the long positions on it:

```json
{"secret":"PASTE_YOUR_SECRET","time":"{{timenow}}","symbol":"{{ticker}}","action":"close","side":"buy"}
```

Close every position on the account:

```json
{"secret":"PASTE_YOUR_SECRET","time":"{{timenow}}","action":"close_all"}
```

From the Mac itself, `tvbridge flatten` does the same without TradingView.

## 5. Recommended alert settings

- **Indicators: trigger "Once Per Bar Close".** The signal is then based on a finished bar:
  it does not repaint and fires once per bar.
- **Strategies:** keep `calc_on_every_tick = false` (the default) so the script decides on
  bar close. The alert fires when the strategy's order fills.
- **Expiration:** the longest your plan allows. Write the date down (see section 8).
- **Notifications:** Webhook URL on. While testing, also tick **Send email**.
- **One alert per chart symbol/timeframe.** The alert keeps the symbol, timeframe, script
  version and inputs it was created with.

## 6. `{{strategy.order.action}}` and why an explicit alert_message is better

Many guides use a generic message such as:

```json
{"secret":"PASTE_YOUR_SECRET","time":"{{timenow}}","symbol":"{{ticker}}","price":{{close}},"action":"{{strategy.order.action}}","market_position":"{{strategy.market_position}}"}
```

`{{strategy.order.action}}` is only `buy` or `sell`; it does not say whether the order
opens or closes. tvbridge handles the common case: when a long is closed, TradingView
sends `"action":"sell"` with `"market_position":"flat"`, and tvbridge treats that as a
**close**. But:

- a **partial exit** (still long afterwards) arrives as `sell` with `market_position`
  `long`. tvbridge cannot close part of a position, so it refuses it (`BAD_ACTION`,
  "PARTIAL_EXIT") and alerts you; the whole position stays open;
- a full exit closes only the side it closed (`sell` + `flat` closes longs);
- a **reversal** arrives as one `sell` with `market_position` `short`: the long is closed,
  then the short entry is checked;
- the generic message carries **no stop-loss**, so every entry is refused (`SL_MISSING`);
  a reversal still closes the old position first, but the new one is not opened.

Explicit `alert_message` JSON (template a) says exactly what to do, with the SL and TP
attached. Use it.

## 7. Test first

1. Keep tvbridge in **paper** mode.
2. Tick **Send email** in the alert. The email shows the exact message TradingView sent;
   paste it into a JSON validator if tvbridge reports `BAD_JSON`.
3. Watch `tvbridge events --limit 20` and `tvbridge status` on the Mac while the alert
   fires. Every rejection shows its reason code (README section 13).
4. `tvbridge send-test --action buy --symbol EURUSD --price 1.08500 --sl 1.08200`
   exercises the Mac side without TradingView.

## 8. Maintenance

- **Delete and recreate the alert after editing the strategy** (code or inputs). An
  existing alert keeps running the version it was created with. Do the same after changing
  the secret.
- **Alert expiry**: on Essential/Plus plans alerts expire after about 2 months. After that
  TradingView sends nothing and tvbridge cannot tell the difference from a quiet market.
  Set a calendar reminder a few days before the expiry date and recreate the alert. Higher
  plans may offer open-ended alerts; check yours.
- TradingView webhooks come from a small published list of IP addresses, which tvbridge
  enforces (`server.tradingview_ips`). If TradingView changes them, update the list.

## 9. Secret handling

- The secret is inside every alert message. TradingView's IP addresses are shared by all
  its users, so **anyone who knows your webhook URL and secret can create their own alert
  that trades your account.**
- Do not share the alert, screenshots of the alert dialog or alert log, or scripts that
  contain the secret. Do not paste it into chats or tickets.
- tvbridge never logs the secret and never echoes it in responses.
- If it may have leaked: generate a new one
  (`python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`), put it in
  `server.secret`, restart the engine
  (`launchctl kickstart -k gui/$(id -u)/com.tvbridge.engine`) and recreate every alert.

## 10. Mirror mode

For a strategy that manages its own stops, targets, trailing and partial exits inside
TradingView and has no per-order `alert_message` (for example "XAU X3 5s MART LAB"). One
alert, fired on **every order fill**, reports the strategy's *resulting position*; tvbridge
then makes the MT5 position on that symbol match it: open, reduce (partial exit), close or
reverse. Read "Mirror mode" in the main README for the safety properties and limits, and
set `mirror.enabled` to `true` in `~/.tvbridge/config.json` first (a `sync` alert is
refused with `MIRROR_DISABLED` otherwise).

Copy this message exactly and replace only `PASTE_SECRET` with your secret:

```json
{"secret":"PASTE_SECRET","time":"{{timenow}}","symbol":"{{ticker}}","action":"sync","position":"{{strategy.market_position}}","size":{{strategy.market_position_size}},"prev_position":"{{strategy.prev_market_position}}","prev_size":{{strategy.prev_market_position_size}},"price":{{strategy.order.price}},"order_action":"{{strategy.order.action}}","order_contracts":{{strategy.order.contracts}},"order_id":"{{strategy.order.id}}","comment":"{{strategy.order.comment}}"}
```

How to create the alert:

1. Open the chart with the strategy on it (the symbol and timeframe you trade).
2. Create an alert, **Condition: the strategy**, and choose **Order fills only** (not
   "alert() function calls").
3. Paste the message above into the **Message** box, with your secret.
4. Notifications: tick **Webhook URL** and enter `https://<your-ngrok-domain>/webhook`.
5. Expiration: the longest your plan allows.
6. **Delete and re-create the alert after every edit of the strategy** (code or inputs): an
   existing alert keeps running the version it was created with.

Fields of a `sync` alert:

| Field | Aliases | Required | Meaning |
|---|---|---|---|
| `action` | | yes | `sync` |
| `symbol` | `ticker` | yes | As for every alert. |
| `time` | `timenow`, `fired` | yes | `"{{timenow}}"`. A sync is accepted up to 15 minutes late (it may carry an exit), but a position is only *opened* within `risk.entry_max_delay_s`. |
| `position` | `market_position` | yes | `long`, `short` or `flat`: the strategy's position after the fill. Anything else: `BAD_POSITION`. |
| `size` | `market_position_size` | unless flat | Position size in strategy units (ounces for gold); the absolute value is used. Missing, zero or not a number while not flat: `BAD_SIZE`. `mirror.units_per_lot` converts it to lots. |
| `price` | `close` | to open | `{{strategy.order.price}}`: the strategy's order price. Without it nothing is opened (`NO_PRICE`); reducing and closing work without. |
| `prev_position`, `prev_size` | | no | The position before the fill. A fill that only reduced the strategy's position never opens one in MT5 (`MIRROR_NOT_AN_ENTRY`). |
| `order_action`, `order_contracts`, `order_id` | | no | The fill that fired the alert; `order_id` keeps two fills in the same second apart. |
| `comment` | | no | The order's comment (first 24 characters are kept). It must not contain a double quote or a backslash, or the message is not valid JSON (`BAD_JSON`). |

Notes:

- No `id` is needed: tvbridge derives one from position, size, time and order id, so a
  TradingView retry is ignored and two different fills never collide.
- Only the newest sync per symbol counts. When several are queued, the older ones are
  dropped (`SUPERSEDED_BY_SYNC`).
- Do not combine a sync alert with buy/sell/close alerts on the same symbol.
- Test in **paper** mode first, with **Send email** ticked, and watch
  `tvbridge events --limit 20`.
